# XY2D-VULKAN
Serialized 2D specific Vulkan Renderer. This rendering model is simple and doesn't focus on multi-threaded command buffer rendering and just provides a basic interface for multi-pass rendering to a single managed command buffer with automated synchronization. The goal of this project is to implement a simple and complete serialized but Frame-in-Flight compliant 2D renderer with the ability to query the GPU for rendering timestamps for accurate in-app profiling (which isn't provided by most simple game engines, Raylib, SDL, GameMaker, etc.).

This model provides 1 frame-in-flight on the GPU and one processing on the CPU using a staggered wait model, where we render a command buffer and then wait for the previous frame to finish rendering and immediately submit the new command buffer to keep the GPU and CPU occupied in parallel. The major benefit of this is that we avoid upkeep and memory usage issues of traditional Frame-In-Flight models which require ping-ponging multi-buffered GPU resources in order to keep rendering in parallel. As long as CPU usage is properly profiled and we keep CPU usage below GPU usage we can keep the GPU fully occupied without double/triple buffering.

The built in `source.cpp` example builds two pipelines, one to render a UV quad and one to render that quad rotated via the camera on the screen. The system when run in debug mode will capture GPU frame timings (2 timestamps, one before/after each render/compute/transfer pass). The example reads out starting timestamp of the current frame and the last timestamp of the previous frame to figure the frame timings (VSYNC enabled by default).
